* Current State
  As of 2026-11-12 three CBMs of the =induct= capabilityType, realm =collective=, are implemented
  here and
  materialized on the dev host (a privileged docker container on an AWS VM): =lcntCore= (Stage 2),
  =lcntBases= (Stage 3) and =lcntMultiMedia= (Stage 4, Container set only). The user considers Stage 3 a
  cut. All uncommitted.

* Architecture
  Each CBM is a leaf =sys/cbm/collective/induct/<name>/cbmProc.spcs= (a pointer to the CBS) in the
  =bro_rawBisosPlatform= tree. Files in =py3/bin/=: =lcntCore-{sbom.pcs,assemble.cs,cbs.pcs}=,
  =lcntBases-{sbom.pcs,assemble.cs,cbs.pcs}=, =lcntMultiMedia-{sbom.pcs,assemble.cs,cbs.pcs}=,
  =cbmProc-lcnt{Core,Bases,MultiMedia}.spcs= (the leaf copies).
  =py3/bisos/lcnt/lcntBasesInfo.py= is the pure source of the bases BXO and its links.
  =py3/bisos/lcnt/lcntMultiMediaInfo.py= is the pure source of the environment (Container, VM or Box,
  override =LCNT_MM_ENV=) and its package sets. The =assemble.cs= =toolchainCheck= verifies, since
  the CBM
  walker and the old scripts report failures as success.

* What Works
  lcntCore: texlive-full, hevea, evince, the Persian fonts (the nested =rawBisos-fonts-sbom.pcs=),
  idempotent;
  =contentProductionExample= builds its PDF (via =seedLcntProc.sh= directly: its =lcntProc.sh= stub
  is stale).
  lcntMultiMedia in a Container: mpv, gimp, imagemagick, pdftk-java, reveal.js and plugins;
  idempotent; the
  check passes. The reveal HTML needs the user's Emacs server (=G_emacsServerPid= must name it).

  lcntBases (rawBisos only): =/de/sys/lcnt= (real directory) with =bxdpt BIB CENTRAL REGISTRY lgpc=
  linked
  into the clone =bxlcnt/bro_lcntBases-rawBisos=, and =/lcnt= to it; idempotent; the check names every
  missing or wrong link. =pres-basic= builds (the user built all three examples and =matoof-son-26=).

* What Is Untested

  The reveal HTML and =matoof-son-26= were built by the user after Stage 3, not by Claude; Claude did
  not run them. The article builds hit a stuck Emacs server (to be looked into) and a =/mode= problem

* Key Design Decisions
  - Everything is core; the environment decides what is installed: Container = PDF and reveal HTML only
    (display-only programs allowed), VM = plus audio, Box = plus video recording. lcntMultiMedia
    checks that
    lcntCore is materialized and never installs it. (User, 2026-11-11.)
  - The legacy scripts (=lcaLaTexBinsPrep.sh=, =lcaJsRevealBinsPrep.sh=) still work on Debian 13 but
    exit 1
    on every run and list packages that no longer exist; the check, not their exit status, is the
    verdict.
  - lcntBases: the bases BXO is the clone =bxlcnt/bro_lcntBases-rawBisos=; =bpoActivate.sh= and the
    usgBpos
    model are the sited BISOS's, where the leaf stays =available=. Nothing is ever linked inside the
    clone.
    =var= and =outputs= are not created, though every build reports the missing =nuBaseDir= list as a
    warning. (User, 2026-11-12.)
  - Out-of-chain: the clone =bro_lcntBases-rawBisos= and =rePublication/fonts= are not in
    =bxRepos-gitist.pcs=; recorded in the AI-Outputs ledger (=blee-binders/evolution=, uncommitted).
  - Out-of-chain: the font "XB Zar" comes from the clone =/bisos/git/auth/bxRepos/rePublication/fonts=
    (https://github.com/rePublication/fonts), which is not in =bxRepos-gitist.pcs=.
